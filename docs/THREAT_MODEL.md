# Threat model — Gather local capstone

Assets: original private media, machine-prepared and human-reviewed notes, API credentials, collections, preferences, agent checkpoints and approved notebook writes. Trust boundaries: browser/API, uploaded media/model, retrieved passages/agents, agent/MCP, interrupt/write action, local app/provider.

Attacker-controlled inputs include queries, speech, visible captions, manual notes and retrieved source content. A malicious clip can contain instructions that attempt to override roles, fabricate evidence or force a notebook write. A model can also invent a fact without any attacker. Model confidence is not evidence.

Controls: localhost-only launch and host/origin checks; same-origin application header for writes; 15 MB media/22 MB request caps; source format checks; HTML escaping and CSP; source content labelled untrusted; source claims carry stable passage IDs; deterministic membership checking and optional model entailment review; missing evidence is omitted with an explicit explanation. Approximate timestamps are labelled. Retrieval sees completed saved sources only and applies collection/topic/saved-date filters before ranking. A lightweight injection heuristic quarantines obvious instruction-like evidence, but has known false positives and evasion gaps. Optional `GUARD_MODEL` adds a JSON-capable OpenRouter classifier for input and retrieved content; configured failures stop the run. This is not a substitute for evaluating a dedicated guard stack.

Agents have explicit per-role tool allow-lists and hard tool/model-call limits. No tool exposes shell, arbitrary file paths, network destinations or account access. MCP servers declare typed input/output, read/write hints and structured errors. Read services mount the source volume read-only in Compose. The action service denies calls without a one-use, short-lived approval capability. The application uses that service in process; the standalone HTTP action process remains deny-by-default because capabilities are never shared over HTTP.

A LangGraph interrupt displays the exact notebook payload. Approve binds to its content hash; edit requires another interrupt; reject writes nothing. The action rechecks source versions and consumes a one-use grant. Idempotent run IDs prevent duplicate notebook rows. Read agents cannot mint a grant. Tool traces scrub key-like strings; request bodies/provider errors are not logged. Keys stay outside graph state.

Residual risks: a valid citation does not establish entailment; a model verifier can be wrong, especially when sharing a family with the writer. The final independent judge must be calibrated against human labels. The regex is not a comprehensive guard model. No multimodal instruction detector, user authentication, per-user authorization, encryption, malware scanner, robust content moderation or hard currency cap is implemented. Call/token limits reduce cost but provider token accounting is observed after each request. Source excerpts can contain sensitive data; do not send private material without consent. Graph checkpoints retain prior evidence until the chat is deleted, so source removal alone does not erase every historic copy.

Test evidence: unit/integration tests cover role denials, direct action denial, stale approval hashes, changed/deleted sources, restart review recovery, origin checks and key absence. Thirty synthetic red-team fixtures cover query and imported-evidence paths; no-key runs only test controls. Before claiming attack resistance, run live defenses-off/on and clean cases, manually review outputs, measure attack success and false-block rate, and include failures.

Feed-to-save boundary: browsing does not authorize model calls. Save & prepare for search explicitly authorizes only the selected source. Feed file access resolves allow-listed IDs to fixed local paths; users cannot supply arbitrary file paths. Automatic indexing is a private derived-data operation and does not mint an agent publish grant. Automatic evidence checks do not constitute human review; this is exposed in note metadata. Unsaved feed items never enter retrieval, failed preparation is excluded, and embedding failure cannot produce Search ready.
